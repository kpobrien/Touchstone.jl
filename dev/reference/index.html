Touchstone.TouchstoneFile — Type
TouchstoneFile{F<:AbstractVector{Float64}, A<:AbstractArray{ComplexF64,3}}
TouchstoneFile(f::F, N::A, frequencyunit::String, parameter::String,
    format::String, R::Float64, version::Float64, numberofports::Int,
    twoportdataorder::String, numberoffrequencies::Int,
    numberofnoisefrequencies::Int, reference::Vector{Float64},
    information::Vector{String}, matrixformat::String,
    mixedmodeorder::Vector{Tuple{Char, Vector{Int}}},
    comments::Vector{String}, noisedata::Vector{Float64})

Store network parameters and Touchstone metadata. The type parameters F and A are the storage types of f and N, respectively. Use touchstone_load, touchstone_parse, or touchstone_file to construct a validated object; the positional constructor stores its arguments without validation or copying.

The fields, in constructor order, are:

  • f: network frequencies in Hz, regardless of frequencyunit.
  • N: complex network parameters with size (numberofports, numberofports, numberoffrequencies). S parameters are dimensionless, Z parameters are in ohms, and Y parameters are in siemens. For H parameters, N[1,1,:] is in ohms and N[2,2,:] in siemens; for G parameters these units are reversed. Off-diagonal H/G entries are dimensionless. Version 1 normalization is removed when reading.
  • frequencyunit: the file unit, "Hz", "kHz", "MHz", or "GHz". This also specifies the units of frequencies in noisedata; f remains in Hz.
  • parameter: the parameter family, "S", "Y", "Z", "H", or "G". H and G require two ports. Parameter, frequency-unit, and format names are case insensitive.
  • format: the file representation, "RI" (real/imaginary), "MA" (magnitude/angle), or "DB" (20 log10 magnitude/angle). Angles are in degrees.
  • R: the positive option-line reference resistance in ohms. For version 1.1, this is the reference resistance of port 1.
  • version: 1.0, 1.1, 2.0, or 2.1. Multiple option-line resistances identify version 1.1 on reading. A single resistance is indistinguishable from version 1.0, including for one-port files, and is reported as 1.0.
  • numberofports: the number of rows and columns of each network matrix.
  • twoportdataorder: "12_21" or "21_12", specifying the order of the off-diagonal entries in two-port data. Version 1 uses "21_12" for two ports; other port counts use "12_21".
  • numberoffrequencies: the number of network frequency records, length(f).
  • numberofnoisefrequencies: the number of noise records, length(noisedata) ÷ 5.
  • reference: one positive reference impedance in ohms per physical port. Version 1.0 requires every value to equal R. Version 1.1 stores these values on the option line and uses them for normalization; version 2 stores them under [Reference] and uses them only for port references.
  • information: lines in the version 2 information section, with their case preserved and comments stored separately.
  • matrixformat: "Full", "Upper", or "Lower". Triangular file formats represent transpose-symmetric matrices; N always contains the full matrix. Version 1 requires "Full".
  • mixedmodeorder: version 2 descriptors (mode, ports) in matrix order. Mode 'S' has one physical port; modes 'D' and 'C' have an ordered pair of physical ports. An empty vector denotes single-ended data. The array N is already in the specified basis; no basis conversion is made.
  • comments: comment text without the leading !, with its case preserved.
  • noisedata: flat five-value records: frequency in frequencyunit, minimum noise figure in dB, optimum source reflection-coefficient magnitude, its angle in degrees, and effective noise resistance in ohms. Noise data require two ports. Version 1 noise resistance is converted to ohms when reading and normalized by R when writing (port 1 in version 1.1).
Touchstone.touchstone_file — Function
touchstone_file(f::AbstractVector, N::AbstractArray;
    frequencyunit="GHz", parameter="S", format="MA", R=50.0,
    version=2.0, twoportdataorder="", reference=Float64[],
    information=String[], matrixformat="Full",
    mixedmodeorder=Tuple{Char, Vector{Int}}[], comments=String[],
    noisedata=Float64[])

Construct a TouchstoneFile from network frequencies f in Hz and physical network parameters N. The array has size (nports, nports, length(f)); see TouchstoneFile for parameter units and metadata fields.

Inputs must use one-based indexing. Views and ranges are accepted. Arrays with element types Float64 for f and ComplexF64 for N are retained; other real frequency and numeric parameter arrays are converted to those types. Reject negative frequencies, nonfinite values, and nonzero values or components that become zero during conversion. Frequencies must increase strictly, including after conversion to the file unit. Numeric keywords R and version accept real values; reference and noisedata accept one-based real vectors. These values use Float64 storage and the same checked conversion. Float16 and Float32 version selectors match supported versions in their input precision before conversion; adjacent values in those types are rejected. Canonical Vector{Float64} metadata vectors are retained.

The keywords select the file representation. References describe the supplied N; changing R or reference does not renormalize S parameters. mixedmodeorder describes the supplied data without transforming its basis. An empty reference uses R for every port. In version 1.1, reference supplies the option-line values and its first value sets R, including for noise normalization. An empty twoportdataorder selects "12_21"; version 1 always uses "21_12" for two ports and "12_21" otherwise. "Upper" and "Lower" require exact transpose symmetry. Use "RI" or "MA" for exact zeros, which have no finite "DB" representation. Information and mixed-mode metadata require version 2. Noise frequencies use frequencyunit, and noise resistance is supplied in ohms. Each comment or information entry must be a single line; information entries cannot contain ! or the section terminator.

Validate the selected file representation one record at a time. The result stores physical arrays and metadata; writing uses their current values.

Examples

julia> f = [1.0e9, 2.0e9]; N = fill(0.5 + 0.0im, 1, 1, 2);

julia> ts = Touchstone.touchstone_file(f, N; frequencyunit="GHz", format="RI");

julia> ts.f === f, ts.N === N
(true, true)

julia> ts.f, ts.frequencyunit
([1.0e9, 2.0e9], "GHz")
Touchstone.touchstone_load — Function
touchstone_load(filename)

Read a Touchstone 1.0, 1.1, 2.0, or 2.1 file and return a TouchstoneFile. Network frequencies f are in Hz and network parameters N use physical units. Noise frequencies retain the file unit; noise resistance is in ohms.

The number of ports is determined from the file contents. No particular filename extension is required. See touchstone_parse to read from IO.

Touchstone.touchstone_parse — Function
touchstone_parse(io::IO)

Read Touchstone data from a seekable stream io at its current position and return a TouchstoneFile. The stream remains open, and an existing stream mark is preserved. Decode complete network records incrementally; malformed input may be rejected before later records are read. Network frequencies are in Hz and network parameters use physical units, as for touchstone_load.

Accept LF, CRLF, or CR line endings and an optional leading UTF-8 byte order mark. Text is decoded as UTF-8 when valid, or as Latin-1 otherwise.

Examples

julia> io = IOBuffer("# MHz S RI R 50\n2.0 0.5 -0.25");

julia> ts = Touchstone.touchstone_parse(io);

julia> ts.f, ts.N[1, 1, 1]
([2.0e6], 0.5 - 0.25im)

julia> ts.frequencyunit
"mhz"
Touchstone.touchstone_save — Function
touchstone_save(filename::String, frequencies::AbstractVector,
    N::AbstractArray; version=1.0, reference=Float64[], R=50.0,
    format="RI", parameter="S", comments=[""], twoportdataorder="12_21",
    matrixformat="Full", frequencyunit="Hz",
    mixedmodeorder=Tuple{Char, Vector{Int}}[], information=String[],
    noisedata=Float64[])

Write network frequencies frequencies in Hz and physical parameters N to filename. See touchstone_file for array dimensions, keyword meanings, and validation. The defaults here select version 1, RI format, and Hz.

Preserve an explicit filename extension. When no extension is supplied, append .sNp for versions 1.0 and 1.1, and .ts for versions 2.0 and 2.1, where N is the number of ports. These defaults follow common naming conventions; the Touchstone 2.1 specification permits .ts for all versions and allows other extensions. Warn when an .sNp extension does not match the port count.

Validate metadata, then encode and validate records while writing a temporary file in the same directory. Replace the destination after successful writing and close using Base.rename. Failures before replacement leave the destination unchanged. Julia versions before 1.12 may fall back to copying if renaming fails. Remove the temporary file on failure. Do not mutate the inputs during a write. An existing regular file retains its read/write/execute permission bits. Replacement does not preserve hard-link identity or follow an existing destination symlink, and it does not guarantee persistence across a system crash. Return nothing.

touchstone_save(filename::String, ts::TouchstoneFile)

Write the current frequencies ts.f, physical parameters ts.N, and metadata of ts to filename. Preserve the selected version, units, representation, references, mixed-mode order, information, comments, and noise data. Recompute port and frequency counts from the arrays.

Validation, filename handling, and file replacement are the same as for the array form of touchstone_save. Return nothing.

Examples

julia> ts = Touchstone.touchstone_file([1.0e9], fill(0.5+0.0im, 1, 1, 1);
           version=2.1, format="RI");

julia> mktempdir() do directory
           filename = joinpath(directory, "network.ts")
           touchstone_save(filename, ts)
           saved = touchstone_load(filename)
           (saved.version, saved.f, saved.N == ts.N)
       end
(2.1, [1.0e9], true)
Touchstone.touchstone_write — Function
touchstone_write(io::IO, f::AbstractVector, N::AbstractArray; kwargs...)

Write network frequencies f in Hz and physical parameters N to io, leaving the stream open. Accept the same keywords and defaults as touchstone_file: version 2, MA format, and GHz file frequencies.

Validate all metadata and encoded records before writing any bytes. Invalid inputs leave io untouched; an IO failure during writing can leave partial output. Do not mutate the inputs during a write. Use touchstone_save for file replacement. Return nothing.

Examples

julia> io = IOBuffer();

julia> Touchstone.touchstone_write(io, [2.0e6], fill(0.5 - 0.25im, 1, 1, 1);
           version=1.0, format="RI", frequencyunit="MHz");

julia> print(String(take!(io)))
# MHz S RI R 50.0
! freq ReS11 ImS11
2.0 0.5 -0.25
touchstone_write(io::IO, ts::TouchstoneFile)

Write the current frequencies ts.f, physical parameters ts.N, and metadata to io. Recompute port and frequency counts from the arrays. Validation and IO behavior are the same as for the array form of touchstone_write. Return nothing.

Touchstone.arraytonetworkdata — Method
arraytonetworkdata(frequencies, N, numberofports, numberoffrequencies,
    matrixformat, twoportdataorder, parameter, frequencyunit, format, R,
    version; reference=Float64[])

Encode physical parameters N and frequencies in Hz as a flat Float64 vector. Each record contains a frequency in frequencyunit, then pairs of numbers in format, ordered by matrixindices.

Apply the inverse of the physical-unit normalization described in networkdatatoarray. DB values are 20 log10 of the normalized magnitude; MA and DB angles are in degrees. For version 1.1, reference supplies one resistance per port; an empty vector uses R for all ports. This low-level helper expects consistent dimensions and metadata. Use touchstone_file for complete input validation.

Touchstone.networkdatatoarray — Method
networkdatatoarray(networkdata, numberofports, numberoffrequencies,
    matrixformat, twoportdataorder, parameter, frequencyunit, format, R,
    version; reference=Float64[])

Decode flat file records into (frequencies, N), with frequencies in Hz and physical network parameters in a ComplexF64 array of size (numberofports, numberofports, numberoffrequencies).

For version 1.0, convert file values with Z = z R, Y = y / R, H11 = h11 R, H22 = h22 / R, G11 = g11 / R, and G22 = g22 R. Off-diagonal H/G entries and S parameters are unscaled. For version 1.1, reference supplies per-port normalization; an empty vector uses R for all ports. Version 2 non-S parameters already use physical units.

DB values describe the normalized magnitude in dB; MA and DB angles are in degrees. Reconstruct triangular matrices by transpose symmetry, without complex conjugation. Use touchstone_parse for complete file validation.

Examples

julia> f, N = Touchstone.networkdatatoarray([2.0, 2.0, 0.0], 1, 1,
           "Full", "12_21", "Z", "GHz", "RI", 50.0, 1.0);

julia> f, N[1, 1, 1]
([2.0e9], 100.0 + 0.0im)

Touchstone.parsenetworkdata! — Function
parsenetworkdata!(networkdata::Vector{Float64}, comments::Vector{String},
    io::Union{IO,TouchstoneReader}, version::Real=1.0; width::Int=0,
    expectedfrequencies::Int=0, expectednoise::Int=-1)

Append encoded network records from io to networkdata, collect comments, and return (numberoffrequencies, recordwidth). Values retain their file units and representation. Frequencies must be finite, nonnegative, and strictly increasing.

A positive width supplies the number of scalar values per record, allowing arbitrary wrapping within a record. In this mode, a positive expectedfrequencies limits the record count and expectednoise=0 rejects [Noise Data]. The complete file parser checks the declared counts. With width=0, infer record boundaries from lines containing a frequency followed by parameter pairs; expectedfrequencies and expectednoise are ignored.

parsenoisedata!(noisedata, comments, io; requireend=false, allowend=true)

Touchstone.parseoptionline — Method
parseoptionline(line::String)

Parse an option line into a TouchstoneOptionLine containing frequencyunit, parameter, format, reference resistance R in ohms, and per-port reference values when present.

Tokens are separated by whitespace and may appear in any order, except that R must be followed by its positive, finite value. Missing parameters default to GHz, S, MA, and R 50. Keep the first occurrence of each parameter and reject unknown tokens. A version 1.1 list after R must finish the option line; its first value supplies R. The complete file parser checks its length against the port count. Strip comments before calling this helper.

Examples

julia> Touchstone.parseoptionline("# MHz Z MA R 75")
Touchstone.TouchstoneOptionLine("MHz", "Z", "MA", 75.0, Float64[])

julia> Touchstone.parseoptionline("# MHz H RI R 75")
Touchstone.TouchstoneOptionLine("MHz", "H", "RI", 75.0, Float64[])

julia> Touchstone.parseoptionline("# R 75 kHz Y")
Touchstone.TouchstoneOptionLine("kHz", "Y", "ma", 75.0, Float64[])
